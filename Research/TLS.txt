TLS certificates come with Public IP, Firebase is recommended for simplicity.

🔐 1. TLS with Firebase
Default Setup:

Firebase already enforces TLS (HTTPS) for all client–backend communication.

You don’t need to manually configure certificates for student devices — browsers and mobile SDKs automatically trust Google’s certificates.

Backend Requirements:

Ensure all API endpoints are served via https:// (Firebase Hosting, Cloud Functions, or Firestore).

No custom TLS setup is required unless you want a custom domain.

Certificates:

Firebase uses Google-managed certificates.

If you map a custom domain (e.g., attendance.mycampus.edu), Firebase provisions and renews TLS certificates automatically via Let’s Encrypt.

You don’t need to distribute certificates to clients — trust is handled by the OS/browser.

👉 Answer: No custom certificates needed for Firebase. Just enforce HTTPS-only endpoints and optionally configure a custom domain if required.


🔐 2. TLS with SQL Server
Here’s what you’d hand to your backend developer:

Enable TLS on SQL Server:

Install a valid SSL/TLS certificate on the SQL Server host.

Configure SQL Server to force encrypted connections (Force Encryption = Yes in SQL Server Configuration Manager).

Certificates:

Use a certificate issued by a trusted CA (e.g., DigiCert, Let’s Encrypt).

Self-signed certificates are possible but require distributing the root cert to all client devices — not practical for mobile students.

Client Setup:

Connection strings must specify encryption, e.g.: Encrypt=True;TrustServerCertificate=False;

If using self-signed certs, TrustServerCertificate=True can bypass validation, but that weakens security.

👉 Answer: Provide a CA-issued certificate, configure SQL Server to force encryption, and ensure backend connection strings enforce TLS.
