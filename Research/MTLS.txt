🔐 What is mTLS?
TLS (Transport Layer Security): Normally, only the server proves its identity with a certificate. The client (student’s browser or app) just checks that certificate and then establishes a secure channel.

Mutual TLS (mTLS): Both server and client present certificates during the handshake.

The server proves it’s legitimate.

The client proves it’s an authorized device/user.

This creates two‑way trust: the server trusts the client, and the client trusts the server.

⚙️ How mTLS Works (Step by Step)
Server Certificate:

The server presents its certificate (signed by a trusted CA).

The client verifies it to ensure it’s talking to the right server.

Client Certificate:

The client presents its own certificate (issued by your CA).

The server verifies it against its trusted CA list.

Handshake Completion:

If both certificates are valid, a secure session key is negotiated.

Communication is encrypted and authenticated both ways.

✅ Why It’s Strong
Even if a student knows their buddy’s login credentials, they cannot log in without the buddy’s certificate.

Certificates are cryptographic — they can’t be guessed or forged easily.

You can store the certificate’s public key or unique ID in your database, linked to the student ID.

Attendance is only marked if the certificate matches the student ID.

⚖️ Key Difference from Normal TLS
TLS: Server proves identity → secure channel.

mTLS: Server + client both prove identity → secure channel + authenticated device/user.

⚙️ Setup Relationship
You cannot have mTLS without TLS — mTLS is built on top of TLS.

TLS is the foundation (secure channel, server identity).

mTLS adds client authentication (device/user identity).

So when you “set up mTLS,” you are really configuring TLS + client certificate validation.

🚫 Risks & Trade‑Offs
Certificate Sharing: If a student exports their certificate and gives it to a buddy, the buddy could still log in. To mitigate, protect private keys with passwords or embed certificates in a controlled mobile app.

Management Overhead: You must handle certificate issuance, renewal, and revocation.

Usability: Students must install certificates correctly — some friction compared to simple password login.
